# Synthetic evaluation dataset

The frozen cheapest-hotel evaluation set is `benchmarks/frozen_eval_v2.json`. It contains 120 complete fixture configurations generated by `booking-synth-v2`. Evaluation consumes those stored configurations directly rather than relying on mutable generator output.

## Diversity axes

Every item derives separate deterministic seeds for content, ordering, prices, visual styling, and layout. Changing one generator axis does not reuse a single global random stream whose draw order could silently perturb the others.

The frozen test set contains:

- 24 items at each result count from 6 through 10;
- exactly 40 top, 40 middle, and 40 bottom cheapest-result placements;
- all ten possible absolute row indices represented;
- exactly 40 close, 40 medium, and 40 wide runner-up price margins;
- 120 distinct price vectors and 120 distinct hotel orderings;
- three currency symbols and five viewport sizes;
- variable card height, card gap, initial card position, image width, price coordinates, and button geometry;
- 12 held-out hotel identities that do not occur in the train or development namespaces.

Prices are sampled independently per item. The cheapest identity, cheapest row, and entire price ranking therefore change instead of receiving a shared offset. The price's screen location also varies through both shuffled row order and explicit layout geometry.

Close-margin cases remain strictly ordered: the runner-up is one to three currency units above the minimum. There are no ambiguous ties in this task version.

## Frozen manifest contract

Each manifest entry contains:

- a stable `item_id`;
- the complete render/action configuration;
- the generator and dataset split identifiers;
- the independent axis seeds;
- the expected cheapest hotel and destination;
- a SHA-256 digest over canonical JSON for that configuration.

The manifest also carries a computed `diversity` summary with stratum counts and unique ordering, price-vector, price-column, and viewport coverage.

Loading a manifest verifies every digest. The test suite also regenerates all 120 items and requires byte-equivalent data, so an accidental generator change fails loudly. Training and development use different content namespaces and should use separate manifests or unbounded generated item IDs; the frozen test manifest must never be sampled for SFT or RL.

## Commands

Regenerate the checked-in manifest deterministically:

```bash
uv run holo-capture generate-eval \
  --split test \
  --count 120 \
  --output benchmarks/frozen_eval_v2.json
```

Run one frozen item through the ordinary capture path:

```bash
uv run holo-capture run \
  --backend scripted \
  --eval-item test-0000 \
  --eval-manifest benchmarks/frozen_eval_v2.json
```

Run a slice of the frozen set:

```bash
uv run holo-capture benchmark \
  --backend scripted \
  --manifest benchmarks/frozen_eval_v2.json \
  --offset 0 \
  --count 20
```

The same manifest should be used for local and future hosted baselines. Activation tracing is not part of the dataset definition and can be enabled only for the local diagnostic subset.

## Vision-resolution diagnostic

`--large-ui-diagnostic` creates an explicitly non-frozen copy of one manifest item with larger typography, price text, and buttons. It preserves the item's viewport, hotel ordering, prices, price-column coordinate, and other layout geometry. This isolates UI scale more cleanly than uniformly resizing a screenshot, which would shrink the controls along with the frame. The variant has a distinct fixture version and `-large-ui` item suffix so it cannot be mistaken for a frozen v2 score.

For example, `test-0035` places the price column at about 58% of viewport width, substantially left of the legacy hotel trace, and places the cheapest result near the bottom:

```bash
uv run holo-capture run \
  --backend local \
  --eval-item test-0035 \
  --eval-manifest benchmarks/frozen_eval_v2.json \
  --large-ui-diagnostic \
  --stop-on-click \
  --trace-generation-steps 64
```

Report this as a resolution/position diagnostic, not as a new test-set result. A clean experiment should cross UI scale with multiple vision-token budgets while holding the task item fixed, then repeat across shifted price columns and cheapest-row strata.

## Remaining domain gap

This generator measures controlled visual comparison, memory across scrolling, and coordinate grounding. It does not reproduce the full distribution of real booking sites. New generator versions can add typography, locale-specific number formatting, discounts, taxes, crossed-out prices, horizontal layouts, and responsive components, but they must use a new version and a separately frozen test manifest rather than mutating v2.
